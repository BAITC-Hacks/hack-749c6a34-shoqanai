# AI Sana Challenge Hub · ShoqanAI

Рабочий интерактивный MVP для HackAlemAi: бизнес превращает короткую потребность в карточку, студенты отправляют предложения, бизнес самостоятельно выбирает команды.

## Запуск

Откройте `index.html` в актуальном Chrome, Edge или Firefox. Установка пакетов, сборка и API-ключ не нужны. Для стабильного хранения данных предпочтителен локальный HTTP-сервер или GitHub Pages. Если установлен Python: `python -m http.server 8080`, затем откройте `http://localhost:8080`.

`tests.html` запускает 18 проверок бизнес-логики. При недоступности Google Fonts интерфейс использует системный шрифт. Основной функционал работает без интернета.

## Целевая аудитория и ценность

- Представитель бизнеса: формулирует задачу без навыка написания ТЗ, получает понятный список пробелов и сравнивает предложения команд.
- Студенческая команда: находит практическую задачу, оценивает готовность бизнеса, предлагает собственный подход и получает баллы за проверенный результат.

## Реализованный сценарий

Черновик → минимум 3 уточняющих вопроса → редактируемая карточка → ручное подтверждение → каталог → отклик → ручной выбор или отклонение → подтверждённый этап (+50 баллов).

Переключатель «Для бизнеса / Для студентов» имитирует роли для защиты. Это не авторизация. Демо-кабинет бизнеса управляет всеми синтетическими задачами.

| Файл | Назначение |

Данные хранятся в localStorage с ключом `aisana-hub-v1`. В разделе «Как это работает» доступен экспорт JSON с актуальным рейтингом карточек. При недоступности хранилища приложение работает в памяти и предупреждает об этом. Опубликованные карточки и отклики сохраняются; незавершённый конструктор живёт до перезагрузки страницы.

## Формула рейтинга

`score = Σ weight[i] × completeAndConfirmed[i]`.

| Критерий | Вес | Поля |
| --- | ---: | --- |
| Контекст и потребность | 20 | context + need |
| Данные и материалы | 20 | data |
| Ожидаемый результат | 15 | result |
| Критерии успеха | 15 | success |
| Ограничения | 10 | constraints |
| Пользователи | 10 | users |
| Связь с бизнесом | 10 | contact + interaction |

Критерий засчитывается целиком, если все его поля содержат непустой текст и подтверждены человеком. Название и компания обязательны для публикации, но не дают баллов. Это проверка полноты, а не автоматическая оценка достоверности текста. За содержательность и измеримость критериев отвечает подтверждающий представитель бизнеса.

В конструкторе отдельно показывается потенциальный балл. Опубликованный рейтинг меняется только после подтверждения обновлённой карточки. Неподтверждённые изменения не влияют на опубликованные данные.

Уровни: 0–39 — черновик; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная.

## Правила каталога и команд

Все опубликованные задачи доступны всем командам, включая рейтинг 0. Сортировка: рейтинг по убыванию, затем новые задачи выше. Есть поиск, фильтр по теме и уровню. Количество откликов не ограничено. Автоматического назначения нет. Бизнес может выбрать несколько команд, отклонить все или оставить предложения на рассмотрении.

За выбор команды баллы не начисляются. После выбора бизнес описывает проверенный результат и подтверждает один демонстрационный этап: +50 баллов. Повторное начисление исключено. Полноценный проектный трекер не входит в MVP.

## AI-функция: честный локальный деморежим

Внешняя языковая модель **не подключена**. В соответствии с условиями кейса используется локальная заглушка: она анализирует отсутствующие поля, задаёт от 3 до 9 вопросов и учитывает направление задачи в вопросе о данных. Ответы переносятся дословно; исходная фраза становится контекстом, неизвестные факты остаются пустыми. Пользователь редактирует и подтверждает карточку.

Промпт доступен в `Hub.prompt` (`domain.js`) и в интерфейсе. Контракт:

```json
{
  "input": {"draft": "Хотим сократить списания в кафе", "topic": "Ритейл", "fields": {"context": "Хотим сократить списания в кафе"}},
  "output": {"questions": [
    {"field": "need", "question": "Что необходимо изменить и почему это важно?"},
    {"field": "data", "question": "Какие данные о продажах доступны команде?"},
    {"field": "success", "question": "Каким показателем измерите снижение списаний?"}
  ]}
}
```

`Hub.validateAssistant` проверяет JSON, число вопросов (3–12), допустимые поля, непустой текст, длину и отсутствие дублей. `Hub.assistant(task, rawResponse)` при неверном ответе возвращает локальные вопросы с `fallback: true`. Кнопка «Тест ошибки AI» показывает этот путь в интерфейсе.

Для настоящей LLM нужен серверный адаптер: передавать промпт и поля на сервер, получать ответ модели, пропускать его через валидатор. Ключи нельзя хранить в клиентском JavaScript. ИИ не определяет победителей и не добавляет фактов.

## Проверки

18 доменных проверок выполнены: веса и границы рейтинга, подтверждение и пересчёт, состав наборов, число вопросов, ошибочный JSON и схема, дубли, безопасные ссылки, принятый этап и защита от повторных баллов. Синтаксис трёх JS-файлов проверен. Дополнительно через обработчики приложения с имитацией DOM выполнен сценарий: черновик → вопросы → карточка → публикация (100 баллов) → отклик → ручной выбор → принятый этап (+50 баллов); проверена генерация всех основных экранов. Это не браузерный E2E-тест. Визуальная проверка в браузере в среде разработки не выполнена: подключённый браузер недоступен.

Ручные проверки перед защитой:

1. Пройдите `DEMO.md` от черновика до принятого этапа.
2. Опубликуйте только название и контекст: карточка с 0 баллов должна быть видна и принимать отклики.
3. Измените опубликованную карточку: до подтверждения каталог сохраняет предыдущую версию, после — пересчитывается.
4. Выберите две команды на одну задачу, отклоните третью.
5. Проверьте пустое предложение, неверную ссылку, пустое подтверждение этапа.
6. Перезагрузите страницу: карточки, отклики и принятые этапы должны сохраниться.
7. Проверьте поиск, оба фильтра и пустую выдачу.

## Границы MVP

Нет общего сервера, синхронизации между браузерами и реальной авторизации. Это однопользовательский демонстрационный прототип с переключением ролей. Контакты и компании синтетические, ссылки `example.com` служат примерами. Для реального запуска понадобятся сервер, база данных, разграничение прав и подключение AI-провайдера.

## Стартовая версия сайта

В папке [starter](starter/README.md) находится отдельная начальная версия: главная страница, форма идеи и сохранение черновика в браузере. Откройте [starter/index.html](starter/index.html) локально или через статический сервер. Эта версия не заменяет основной MVP.
